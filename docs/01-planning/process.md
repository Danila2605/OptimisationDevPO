# Процесс команды

## 1. Цель

Выбрать методологию работы, настроить доску задач с WIP-лимитами, сформулировать Definition of Ready и Definition of Done для проекта «СтройМаркет».

## 2. Выбор методологии

Выбрана методология **Scrumban** — гибрид Scrum и Kanban.

### Обоснование по факторам

| Фактор | Проявление в проекте | Вывод |
|---|---|---|
| Размер команды | 1 человек, но с внешним ревью партнёра | Полноценный Scrum с ролями избыточен; Kanban проще |
| Изменчивость требований | Состав MVP может уточняться после ревью и обратной связи | Kanban позволяет менять приоритеты без жёстких спринтов |
| Потребность в планировании | Нужно зафиксировать MVP, ёмкость, зависимости и дату | Берём из Scrum: планирование итерации, review, retrospective |
| Поток задач | Задачи идут непрерывно, часть историй зависит друг от друга | Kanban-доска и WIP-лимиты помогают видеть очередь и узкие места |
| Контроль незавершённой работы | Один человек склонен к многозадачности | WIP-лимиты критичны, особенно «В работе = 1» |
| Частота поставки | MVP нужно собрать к защите ЛР3, далее — инкрементально | Итерации по 1 неделе + непрерывный поток |

**Итог:** Scrumban даёт еженедельное планирование и обзор, но не вводит жёсткие спринты и позволяет быстро переприоритизировать бэклог.

## 3. Доска задач

Доска ведётся в Plane. Колонки отражают реальные этапы работы:

| Колонка | Назначение | WIP-лимит |
|---|---|---:|
| Бэклог | Все истории, включая post-MVP | без лимита |
| Готово к работе | Истории, прошедшие DoR | **3** |
| В работе | Истории, которые сейчас реализуются | **1** |
| Готово | Истории, прошедшие DoD | без лимита |
| Отмененно | Отменённые истории | без лимита |

Дополнительно можно использовать метки `mvp`, `post-mvp`, `step-1…step-6`, `needs-split`.

### Обоснование WIP-лимитов законом Литтла

Закон Литтла:

WIP = Throughput × Lead Time (Пропускная способность × Время выполнения заказа)

## 4. Definition of Ready
История готова к работе, если:

□ есть ID, заголовок и формулировка «Как …, я хочу …, чтобы …»;
□ есть не менее двух критериев приёмки в формате «Дано / Когда / Тогда»;
□ история прошла проверку по INVEST или разбита;
□ проставлена оценка в story points;
□ указаны зависимости и обязательность для MVP;
□ понятна ценность для пользователя или бизнеса;

## 5. Definition of Done
История считается готовой, если:

□ реализованы все критерии приёмки;
□ код/контент проверен по чек-листу;
□ выполнено ревью вторым участником/партнёром, замечания закрыты;
□ пройдены ручные проверки по критериям «Дано / Когда / Тогда»;
□ обновлены документы в docs/, если изменилось поведение продукта;
□ изменение задеплоено на тестовый стенд или проверено локально по инструкции;
□ нет критичных дефектов;
□ issue закрыта, PR смержен, статус на доске переведён в «Готово».
Для контентных историй (US-01, US-02, US-06) вместо кода проверяются тексты, ссылки, телефоны, адреса и отображение на мобильном/десктопе.
